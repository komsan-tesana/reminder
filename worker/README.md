# Push relay (Cloudflare Worker)

ส่วนเสริมที่ทำให้แอปเด้งแจ้งเตือนได้ **แม้ปิดแอปหรือล็อกจอ** (Web Push) เว็บบน GitHub Pages ไม่มี server จึงส่งเองไม่ได้ Worker ตัวนี้ทำหน้าที่เดียว คือ "ปลุกเครื่อง" ตามเวลาที่แอปบอก

## ข้อมูลที่ส่งมาที่ server
เก็บเฉพาะ **ที่อยู่ปลายทาง push ของเครื่อง + กุญแจของมัน + รายการเวลา (epoch วินาที) ที่ต้องปลุก**
ไม่มีชื่อลูกค้า เลข SO หรือข้อความแจ้งเตือน ตัวข้อความอยู่ในเครื่อง (IndexedDB `reminder-push`) แล้ว service worker ประกอบแสดงเองตอนถูกปลุก ข้อมูลที่ส่งใน push มีแค่ `{"due": <เวลา>}` (เข้ารหัสตาม RFC 8291)

## สิ่งที่ต้องมี
- บัญชี Cloudflare (แผนฟรีพอ) และ Node 18+
- iPhone: iOS 16.4 ขึ้นไป และต้องเพิ่มเว็บลง **หน้าจอโฮม** ก่อนจึงจะรับ push ได้

## ติดตั้ง (ทำครั้งเดียว)
ทุกคำสั่งรันในโฟลเดอร์ `worker/`

```bash
cd worker
npm install
npx wrangler login
```

1. สร้าง KV namespace (หรือสร้างใน dashboard: Workers & Pages → KV) แล้วนำ `id` ไปใส่ใน `wrangler.toml` ตรง `[[kv_namespaces]]` (binding ต้องชื่อ `KV`) ถ้าคุณสร้างไว้แล้ว และ id ใน `wrangler.toml` ตรงกับของคุณ ข้ามขั้นนี้ได้
   ```bash
   npx wrangler kv namespace create transport-calendar-push
   ```
2. สร้างกุญแจ VAPID
   ```bash
   node scripts/gen-vapid.mjs
   ```
   - **PUBLIC KEY** → ใส่ใน `../src/lib/pushConfig.ts` (`VAPID_PUBLIC_KEY`)
   - **PRIVATE KEY** (บรรทัด JSON) → เก็บเป็น secret ห้าม commit:
     ```bash
     npx wrangler secret put VAPID_PRIVATE_JWK
     ```
3. ตั้ง **อีเมลติดต่อ** ของคุณเป็น secret เช่นกัน (push service ใช้ติดต่อถ้า Worker ทำงานผิดปกติ) เก็บเป็น secret เพื่อไม่ให้อีเมลไปอยู่ใน repo สาธารณะ:
   ```bash
   npx wrangler secret put VAPID_SUBJECT      # พิมพ์เช่น mailto:you@your-domain.com  (หรือลิงก์ https://...)
   ```
   ถ้าจะใช้โดเมนอื่นนอกจาก GitHub Pages ให้แก้ `ALLOWED_ORIGINS` ใน `wrangler.toml` (ค่านี้ไม่ลับ)
4. deploy ด้วยสคริปต์ (รันจากรากโปรเจกต์):
   ```bash
   npm run deploy:worker -- --dry-run         # ลองก่อน: ตรวจ/ทดสอบ/บันเดิล ไม่ deploy ไม่ต้องล็อกอิน
   npm run deploy:worker -- --write-config    # deploy จริง แล้วเขียน URL + PUBLIC KEY ลง pushConfig.ts ให้
   ```
   สคริปต์ ([scripts/deploy-worker.sh](../scripts/deploy-worker.sh)) จะ: ตรวจ `wrangler.toml` (id ของ KV, ไม่มี secret หลุดในไฟล์) → ติดตั้ง dependency ถ้ายังไม่มี → ทดสอบ + ตรวจชนิดข้อมูล → ตรวจล็อกอินและ secret → `wrangler deploy` → ตรวจ `/health` → เทียบ URL และ PUBLIC KEY กับ `src/lib/pushConfig.ts` (เตือนถ้ากุญแจไม่ตรงกับที่ Worker ใช้จริง)
   ไม่ใช้สคริปต์ก็ได้: `cd worker && npx wrangler deploy` จะได้ URL เช่น `https://transport-calendar-push.<ชื่อ>.workers.dev` แล้วใส่ใน `../src/lib/pushConfig.ts` (`PUSH_SERVER_URL`, ไม่มี `/` ท้าย)
5. กลับไป deploy แอปตามปกติ (`npm run deploy` จากรากโปรเจกต์) การ deploy แอปไม่แตะ Worker คนละอย่างกัน

ตรวจว่า Worker ทำงาน: เปิด `https://<URL ของคุณ>/health` ต้องได้ `{"ok":true,"publicKey":"B…"}` (publicKey คือค่าที่ต้องใส่ใน `VAPID_PUBLIC_KEY` ถามจาก Worker ได้เสมอ ไม่ต้องจำ) ถ้าลืมตั้ง secret หรือใส่ค่าผิด จะได้ `{"ok":false,"error":"…"}` พร้อมบอกว่าต้องตั้งตัวไหน (cron จะบันทึกข้อความเดียวกันใน log และไม่ส่งอะไร)

## ใช้งานบน iPhone
1. เปิดเว็บใน Safari → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม** → เปิดจากไอคอนนั้น
2. 🔔 เตือน → **เปิดแจ้งเตือนแบบ Push** → กดอนุญาต
3. ลอง **ทดสอบ** แล้วล็อกจอ รอประมาณ 2 นาที ควรเห็นแจ้งเตือน "ทดสอบ Push"

## ทำงานยังไง
- แอปคำนวณ "ควรปลุกเมื่อไร" (สรุปรายวันตามเวลาที่ตั้ง + รายการเตือน) เก็บข้อความไว้ในเครื่อง และอัปโหลดเฉพาะเวลา (`POST /sync`) ทุกครั้งที่ข้อมูลเปลี่ยนหรือเปิดแอป
- cron ทุกนาทีดูดัชนี (คีย์ `index` ใน KV: เวลาปลุกที่เร็วที่สุดของแต่ละเครื่อง) แล้วส่ง push เปล่าๆ (มีแค่ `due`) ให้เครื่องที่ถึงเวลา ถ้า push service ตอบ 404/410 จะลบเครื่องนั้นทิ้ง
- ปลุกที่ช้าเกิน 6 ชั่วโมงจะถูกทิ้งแทนการเตือนเรื่องที่ผ่านไปแล้ว เครื่องที่ไม่ซิงก์เกิน 120 วันจะหมดอายุเองด้วย TTL ของ KV

## โควตาฟรีของ KV (ออกแบบให้อยู่ในนี้)
KV แผนฟรี: อ่าน 100,000 ครั้ง/วัน, **เขียน 1,000 ครั้ง/วัน**, **list 1,000 ครั้ง/วัน** cron ทุกนาทีจึงไม่ใช้ `list()` เลย
- นาทีที่ไม่มีอะไรถึงเวลา = อ่าน 1 ครั้ง ไม่เขียน (≈1,440 อ่าน/วัน)
- ซิงก์ที่ไม่มีอะไรเปลี่ยน (แอปซิงก์ทุกครั้งที่กลับมาเปิดหน้า) = ไม่เขียนเลย
- ปลุกหนึ่งเครื่อง = เขียน 1 ครั้ง (บันทึกตารางที่เหลือ) + ดัชนีอีก 1 ครั้งต่อรอบ cron
- ประมาณการ: ผู้ใช้หลักสิบเครื่องอยู่ในโควตาฟรีสบายๆ ถ้ามากกว่านั้นหรือข้อมูลเปลี่ยนบ่อยมาก ให้ใช้แผน Workers Paid ($5/เดือน)

## ข้อจำกัด
- ต้องเปิดแอปให้ซิงก์อย่างน้อยหนึ่งครั้งหลังข้อมูลเปลี่ยน (ถ้าข้อมูลเปลี่ยนแล้วไม่เคยเปิดแอปอีก เวลาปลุกจะยังเป็นของเดิม)
- cron ละเอียดระดับ 1 นาที เตือนอาจช้าได้ถึงประมาณ 1–2 นาที
- ถ้าผู้ใช้ลบแอปหรือถอนสิทธิ์ ระบบจะรู้ตอนส่งครั้งถัดไปแล้วลบเครื่องออกเอง
- ถ้าเปลี่ยนกุญแจ VAPID ต้องให้ทุกเครื่องปิดแล้วเปิด Push ใหม่
- ดัชนีเป็นคีย์ร่วมที่ KV ไม่มีการล็อก ถ้ามีสองคนซิงก์พร้อมกันพอดี รายการของคนหนึ่งอาจหายจากดัชนี แต่ซิงก์ครั้งถัดไป (เปิดแอป/ข้อมูลเปลี่ยน) จะซ่อมให้เอง

## พัฒนา/ทดสอบ
```bash
npx wrangler dev          # รัน Worker ในเครื่อง (ใช้ KV จำลองในเครื่อง)
#   secret สำหรับรันในเครื่องใส่ในไฟล์ worker/.dev.vars (ถูก .gitignore ไว้แล้ว):
#     VAPID_SUBJECT=mailto:you@your-domain.com
#     VAPID_PRIVATE_JWK={"kty":"EC",...}
npx tsc -p .              # typecheck
```
เทสต์ของ Worker รันรวมกับโปรเจกต์หลัก (`npm test` จากราก) ใช้ KV จำลองในหน่วยความจำที่นับจำนวนการอ่าน/เขียน เพื่อพิสูจน์ว่าไม่เกินโควตา
